# 工作模式、规则板块与拓展工具

## 目标实现

AI 对话提供讨论需求、制定计划、执行任务三种并列模式。讨论/计划支持仅 Docs 的文档写入，执行任务才关联 Unity 变更审批。规则案固定工程事实、执行细则、项目索引、模板四板块，规则无状态；操作指南与可调用拓展工具独立展示，配套使用说明。

## 技术方案

ProjectContext 统一规范根路径与工程身份，工程内 .karolina/state 保存审批、工作模式偏好和工具结果，由 Git 忽略；启动固定显示AI对话，不保存或恢复上次页面。旧本机状态仅迁移工作模式并移除旧页面记录；浏览器端口变化不影响存储。工具声明在 Docs/tools/registry，说明在 Docs/tools/guides；Unity MCP 与外部程序通过 IExtensionToolRunner 接口接入，参数以 JSON 对象和原生进程参数列表传递。

### 代码质量与演进边界

按高内聚低耦合、关注点分离、依赖倒置、清晰边界、可测试可观测、简单实用和演进式设计持续改进。优先从真实混杂职责提取服务：协议连接与本地持久化有可替换端口，状态服务由唯一拥有者管理，时间可注入；HTTP映射与执行流程分开组织，前端政策计算与DOM绘制分开。现有快照、审批来源、权限、构建暂停和协议终态合同保持。文件拆分本身不代表完整应用层解耦；不为每个类型增加接口，不新增依赖或框架。

## 边界情况

注册不执行，必须人工调用。外部程序使用当前 Windows 用户权限，声明只读不等于操作系统沙箱；由注册者说明真实写入范围。工具声明需说明真实写入范围；人工直接调用不强制关联计划/任务，也不冒充Agent变更。执行任务模式仍在写入前关联执行计划并建立审批基线。调用共享工程锁，真实失败/取消/超时记录可见。Unity 构建标记的调用只发一次，用户登记构建结束前禁止后续 Unity 操作。任务审批不批准规则或文档草稿，也不替代真实玩法验收。

## 验收条件

完全退出重开仍能看到已保存的任务审批条目和原始基线；展示排除.meta和用户确认的人工导入资源；三种模式和写入范围在服务端生效；规则导航仅四板块；指南从工具页阅读；Unity/外部工具能注册并人工调用，记录真实结果，人工调用有独立工具运行回执；能核对来源的Agent写入进入任务审批。

## 附录

本轮审查七原则：高内聚低耦合、关注点分离、依赖倒置、清晰边界、可测试可观测、简单实用、演进式设计。当前架构问题和剩余改进记录在 Karolina 架构审查事实中。

## 需求演进

### 2026-10-05 · 人工工具调用与Agent任务分开

工具页不再强制计划或继续任务；同页注册多个相关调用函数。人工主动调用不是Agent写入，不能仅凭时间窗口认领到任务审批。执行任务写入的基线、来源证明和计划边界继续生效。

### 2026-10-05 · MVP代码质量改进

用户要求按七项原则改进现有代码质量。明确这一批集中在说明进度服务、协议连接边界、宿主职责组织与前端纯政策/视图分离；保留现有数据格式与用户交互。未来新增Harness、图谱或MCP时再按真实需求扩展，不提前实现整套通用调度。

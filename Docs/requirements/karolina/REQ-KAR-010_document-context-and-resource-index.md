# 文档参考与工程资源索引

## 目标实现

统一混合参考列表，默认隐藏废弃需求/关闭计划；按编号自然倒序。每份文档最多10个标签。计划分别登记事前 plannedChanges 与事后 resourceRefs，引用计划时默认包含关联资源且可逐项取消。需求演进仍在正文，界面派生时间线；标题目录支持全部层级与折叠。Ctrl+滚轮只缩放Markdown正文，导航、目录、对话输入与Windows窗口不随之缩放。

## 技术方案

元数据与正文分离；独立索引更新入口允许关闭计划/规则维护标签而不重启生命周期。真实资源需规范项目相对路径、无链接、校验存在与哈希；历史资料仅按精确证据关联，未知项列清单。

### 混合资料与演进阅读

参考候选先筛选 requirement/plan，默认去掉废弃/关闭项；按独立元数据 code 的数字序列自然倒序比较，同编号保留稳定顺序。显示标题与状态，不用编号代替可读名称；每项显示“需求”或“计划”类型标记，可按类型筛选。搜索支持标题/编号/标签的部分文字及顺序字符匹配，多个词分别匹配；#词只匹配标签。标签目录可浏览、点击筛选，不要求用户先知道标签。历史项可以主动显示，重新隐藏时取消其参考勾选。

需求历史仍只存正文的“需求演进”章节：从其子标题生成可展开的时间线，最近条目先展示，每条保留完整 Markdown 内容。没有可解析子标题时展示原章节，不编造日期；元数据/关联在另一入口维护。目录按 h1–h6 的实际父子层次建树，当前最浅级默认展开，其下层可折叠。目录提供展开全部/折叠子级，窄窗口有“标题目录”独立入口。Ctrl+滚轮仅在Markdown阅读区域调整正文样式，范围60%–200%，偏好持久保存并可重置；WebView2原生缩放固定为1，阅读区外的Ctrl滚轮不改变应用缩放。

### 索引合同与数据流

每份案的 tags 是独立字符串数组，保存时去空、修剪、大小写无关去重，最多10项，每项最多40字符。规则无生命周期；关闭计划允许补充标签和真实关联，正文与事前预估冻结。元数据写入须匹配读取时的哈希，不覆盖外部修改。

计划 plannedChanges 每项包含 path、operation（add/modify/delete）、reason；新计划从准备进入执行前必须登记。resourceRefs 每项包含 path、evidence，可附 hash、operation、reviewId；与预估分开，整体审批通过后关联确认属于Agent的实际变化。旧计划缺少预估时明确标记，不能追溯假造。

参考计划时读取资源列表，前端默认全选；发送对话时按计划ID提交明确的路径集合，空集合代表不选。服务端复核路径确属该计划，只把所选路径和关联依据加入上下文，资源正文由Harness按需读取。计划阅读提供“关联代码与资源”按钮，列出真实路径、关联依据及当前存在情况，可在文件管理器定位；本期不宣称内置Unity资源预览。规范路径只允许工程内部文件，拒绝绝对路径、上级路径、重解析点、.meta和生成目录；哈希是关联时快照，不能代替测试结论。

## 边界情况

并发修改与陈旧版本必须可见拒绝；不能把机器静态摘要视为行为验收。保留既有美术交互、已有Unity改动及审批存档。失败不补造成功。

后续任务删除的历史文件仍保留原关联和哈希，资源定位失败明确提示，对话上下文标明文件缺失；新增关联必须能核对真实文件，审批中的删除则保留删除事实。历史迁移只解析明确文件路径，不扩展整个目录猜测归属，待确认项单独列出。保存资料索引不能丢失正在编辑的正文草稿。

## 验收条件

通过对应计划的机器检查与独立Agent审查，用户操作确认后才能关闭。禁止截图验收。

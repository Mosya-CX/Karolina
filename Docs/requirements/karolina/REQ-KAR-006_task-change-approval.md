# 任务变更审批与反馈再执行

## 目标实现

用户审查的是一份计划在本次任务中造成的 Unity 文件变化，以及本次整体做了什么。Karolina 移除 Git 工作台，提供任务列表、简洁摘要、文件差异、逐文件审批和整体审批。不提供 GitHub 登录、暂存、Commit、Push、Pull、提交历史或 Stash。

一次任务绑定一份具体计划，可以有多轮执行；AI 对话中的参考需求/计划仍允许空选和多选。只读讨论无需任务审批。项目写入前需选择执行计划或继续已记录的任务。

## 技术方案

### 开始基线与实际变化

在 Codex 写入轮次开始前记录 Assets、Packages、ProjectSettings 下真实路径、大小和 SHA-256；包含代码、资源、配置和 .meta，不依赖 Git 仓库、HEAD 或暂存区。开始前已有改动成为基线的一部分，不归入本次任务。文本快照保存于工程内被 Git 忽略的 `.karolina/state/reviews`，不写 Unity 资产或工程 Git。

外部 Harness 或人工操作可先点击“开始记录外部任务”，再执行，最后提交差异。不能事后从 HEAD 推断任务归属。当前第一版对整个目录做内容快照，同期其它 IDE/Unity 的写入也进入差异，无法证明作者；此限制必须可见。

### 差异与资源

文本和 Unity YAML 显示真实前后行号、增加/删除/相同行，可点击变更前或变更后行号定位意见。新增、删除、空文件、.meta、仅大小写重命名均不能漏掉。普通资源移动显示旧路径删除和新路径新增；仅大小写移动显示对应原路径。没有改动的文件不列出。

审批列表默认隐藏 `.meta`，可以通过“显示 .meta”开关查看，偏好随工程保存。过滤只作用显示，不改变完整任务快照、已有意见或审批范围；整体批准按钮与确认内容明确隐藏数量。

二进制、非 UTF-8、超过 2 MB 或前后合计超过 6000 行的文件显示类型说明、大小及完整 SHA-256，明确转到 Unity/对应编辑器查看细节；不截断后声称完整文本差异。本期不解析 Unity 场景/Prefab 的对象语义、纹理像素变化或模型顶点变化。

### 逐文件与整体审批

逐文件可通过、不通过，或单独保存意见。驳回必须至少一条文件整体或定位行的解释。意见绑定文件路径、前后内容指纹及任务修订；行号必须属于该版文本。重新生成差异时，只保留内容及路径完全未变的文件结论；变化的文件重新待审批，旧退回意见保留在任务轮次证据中。

整体批准可一次批准全部尚未逐文件决定的变化；存在不通过文件时禁止整体批准。整体退回可依据文件驳回或整体意见，不能无原因退回。文件审批和整体审批均重新核对当前内容，拒绝旧页面修订、内容已变化、路径已变化或增删文件已不同的审批。

批准记录表示这版内容被用户接受，不提交、复制、合并或回滚工程文件，也不宣布机器测试成功。任务审批状态为执行、待审批、待再执行、已通过；它与计划准备/执行/测试/校正/验收/关闭的六阶段分开。计划阶段通过文档信息面板维护，任务整体批准不自动关闭计划。

### 返回执行

Codex 真实 completed 终态后生成任务差异，Agent 最后输出作为可编辑摘要；无总结时明确要求补充，不补造已完成目标。失败、停止、断连或初始化回执未知保存真实运行状态，仍可在停止后手动生成变化供审查。

整体不通过后进入待再执行。“返回再执行”成功载入原会话后，把文件/行意见和整体意见填入 AI 指令，用户可修改指令、模型和访问权限，发送后恢复同一任务，保留最初基线；没有原会话的外部任务建立新会话。原会话载入失败不绑定到其它聊天，不自动发送修复指令。

## 边界情况

- 驳回保留已写文件，不自动删除或恢复 Unity 资产，不破坏开始前工作。
- 快照含链接目录/文件或读写冲突时可见失败，不能漏扫后批准；任务记录损坏不作为成功。
- 页面保存期间锁定审批编辑和切换；失败保留草稿。跨页面保留未保存草稿及退出提示；换任务明确确认放弃后重新读取记录。
- 审批是变更后的人工验收记录。Codex 命令/写入扩权审批仍是独立安全请求，两者不能互相代替。当前项目直接写入，所以文件不通过不意味着该文件从未落盘。
- 多 Harness 自动执行、语义资源图、自动修复测试系统和选择性合并不是本次范围。

## 附录

TaskReviewStore 保存工程独立 reviews/*.json 及按 SHA-256 定位的文本快照。编号、关联计划、轮次、摘要、实际运行身份/状态、文件意见与审批版本属于任务记录，不写成需求历史或计划演进。需求有正文演进，计划继续独立元数据与六阶段。

## 需求演进

### 2026-10-02 · 用户取消 Git 功能，改为计划任务审批

变更前：Karolina 内建 GitHub 账号、所选提交、推送/拉取、历史及 HEAD 差异。

变更后：移除上述 Git 产品能力，以任务开始时真实 Unity 内容为基线，审查本次计划任务的文件和整体摘要；逐文件/整体可通过或驳回，意见支持文件及行定位，整体退回后携意见再次执行。

原因：用户实际需要任务变更审批制度，Git 工作区不能准确说明一次计划做了什么。沿用标准 WebView2、Codex 对话、文档与连接状态，新增纯文件快照及审批记录，不新增第三方依赖，不修改 Gameplay 合同。由 PLAN-KAR-005 实施，旧 Git 条款退役；版本管理改用用户现有外部工具。

### 2026-10-02 · 已中断三狼重做的事后整理

用户要求将已有三狼变更整理为审批条目用于测试。新增明确授权下的维护导入：候选文件附收录依据、历史参考来源和当前内容指纹，未选既有文件保留整理时状态。页面明显展示事后来源，不能声称已丢失实现被还原或该差异全由本任务产生。原正常执行前快照合同保持；真实条目不由机制测试自动批准。

### 审批持久位置统一与原记录恢复

变更前：记录以本机应用数据目录和工程散列定位。用户完全退出后，原生程序的列表为空；命令环境虽能看到旧文件，却不足以证明 GUI 也能读取。另有尾分隔符造成身份不同的边界。

变更后：规范工程根路径，审批与快照改存 `.karolina/state`，共享锁也放入同一工程。首次恢复保留原记录编号、意见、修订及文本内容；读取再写入避免继承旧 EFS 属性。重开恢复页面位置与选中任务。迁移冲突可见且不覆盖人工数据。

原因与兼容：让所有启动方式读取同一工程状态，由 PLAN-KAR-006 实施。旧本机文件保留取证，不重新从 HEAD 生成三狼基线；恢复不自动批准任务、不关闭计划、不修改 Unity 文件。此次原三狼条目仍待审批，100文件，重做中断的事实不变。

### 默认隐藏 Unity 元数据文件

用户希望审批页面自动去掉 .meta 列表噪声。页面默认隐藏这类文件，提供显示开关并保存偏好；切换不删除文件、记录或意见。整体审批仍对应完整任务文件集合，按钮和确认内容明确包含隐藏 .meta 数量。单文件审批只作用当前文件，隐藏文件不被自动单独批准；隐藏状态下的驳回仍阻止整体通过。

# 文档生命周期与工作台交互

## 目标实现

需求只有激活/废弃并保留语义变动历史；计划按编码顺序浏览，有执行、验收和关闭边界；规则不显示状态。正文阅读顺畅，切换目录分类保留正在阅读的文档标题。元数据、关联、来源与证据从独立按钮浏览，只有需求提供演进入口。

任务审批替代 Git 工作台，具体范围由 REQ-KAR-006 定义。AI 对话顶部独立放置 Codex 与 Unity 连接/操作，刷新模型账号和运行详情只在此页面显示。

## 技术方案

沿用 .NET 本地服务与已授权 WebView2 控件，本次任务审批不新增第三方包。文档目录缓存并由 FileSystemWatcher 通知失效，显式刷新重载索引，写入时直接核对磁盘身份与生命周期，正文一次读取后计算 hash，元数据独立按需读取。前端缓存阅读内容并后台核对，异步请求采用序列保护，保留未保存编辑。需求语义修改通过多行说明记入正文“需求演进”，技术来源与恢复信息另存。

计划使用 code 自然排序；requirements 是稳定 ID，requirementRefs 是标题/状态/版本/章节/路径/hash 的引用快照。关闭计划服务端拒绝保存执行正文。历史独立批次从经过核验的恢复快照重新整理，源码核查与用户人工测试分开登记。

任务基线和审批存于工程独立本机目录，文件路径/内容指纹随任务修订核对；快照和意见不混入文档元数据。

## 边界情况

计划关闭后不能重启，取消作为关闭结果登记；旧类型已替换时说明当前对应实现。源码证据不能虚构真实测试通过；配套构建未跑、专用测试不完整、金币合同冲突与未定义目标策略继续保留。Git 操作交由外部工具，Karolina 不读取账号、恢复索引锁或写入索引。快速切换、保存期间继续输入和外部修改不能覆盖用户编辑。

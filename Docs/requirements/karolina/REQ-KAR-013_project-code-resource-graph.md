# 工程代码与 Unity 资源关系图谱

## 目标实现

Karolina 为当前 Unity 工程建立可搜索、可追溯的 CodeGraph 与 ResourceGraph。用户可从脚本、类型或 Unity 资源进入，查看与其相连的代码和资源，并可将图谱节点作为 Agent 上下文入口。图谱是工程事实索引，不是架构设计或执行权限系统。

## 技术方案

索引仅遍历 `Assets`、`Packages`、`ProjectSettings` 中的项目文件，忽略 `.meta` 展示节点和生成目录。以规范项目相对路径及稳定符号标识节点；代码图包含脚本文件、C# 类型声明、文件包含的类型、可无歧义解析的类型引用；资源图用 `.meta` 中的 GUID 建立资源身份，并从可读 Unity 序列化文件的 GUID 引用建立资源关系。扫描只读，不改写 Unity 文件、GUID、场景或资源。

图谱快照保存在 `.karolina/state/project-graph.json`，仅在用户请求时重建。构建时通过状态端点提供实际扫描进度、跳过数、索引时间、错误和容量限制；状态写入原子替换。符号/引用无法唯一识别时不猜边，二进制、过大文件和无法读取的文件记录为跳过信息。资源引用边仅表示文件引用，不表示运行时加载或语义依赖。

UI 提供“工程图谱”页、代码/资源类型筛选、模糊搜索、节点详情及入边/出边列表。列表显示标题、路径、关系和来源，不把内部编号作为主要名称。用户可从节点将精确路径/类型信息带入对话参考资料。图谱资料须附带索引时间与工程根路径，提醒 Agent 重新核对可能过期的源码。

## 边界情况

工程不是 Unity 项目、目录不存在或无可索引内容时提供可读状态。遇到重解析点/链接目录时拒绝穿越并将风险显式列出；扫描容量达到边界时停止而非静默返回不完整“完整图谱”。外部文件在扫描中变化时保留错误/过期状态并允许重建。缺失 `.meta`、重复 GUID、重复短类型名不会推断确定关系。`.meta` 仅内部解析身份，不在图谱列表或审批中显示。

图谱信息不修改、批准或归属文件，也不能证明 Agent 作者、资源运行表现或测试通过。旧索引在重建失败时保留，但必须显示上次成功时间及失败状态。

## 验收条件

- C# 文件和类型可被检索，文件包含关系与可唯一识别的类型引用可浏览。
- 资源 GUID 引用能在互相引用的可读 Unity 资源之间建立关系；脚本 GUID 能连到脚本节点。
- 搜索无结果、重复 GUID、无法解析的关系、二进制文件、链接目录、取消/失败和超量均显示真实状态，不生成臆测边。
- 重新索引期间 UI 可读取进度；失败后保留最近成功快照且显示其时间。
- 从节点加入对话资料仅添加选定上下文，不改审批或执行计划。
- 不修改 Unity 资产，不要求截图验收。

## 附录

索引主键由节点类型和规范化路径/符号名确定，边由起点、关系、终点去重并稳定排序。索引文件包含 schemaVersion、规范化工程根路径、创建时间、遍历统计、错误和节点/边；版本不兼容时拒绝按新格式读取并提供重建入口。

# 统一设置页与模型挡位预设

## 目标实现

Karolina 提供一个统一设置页面，集中维护本工程的 Agent 默认模型/挡位、有限修复策略、工程图谱索引入口及外观主题；AI 对话仍允许逐任务选择模型、挡位和访问权限并覆盖默认值。默认模型挡位偏低，设置变更可见且保存后重启仍有效。

## 技术方案

在 `.karolina/state/settings.json` 保存项目级设置，沿用 ProjectContext 的根路径校验、路径隔离、原子写入和 JSON 兼容方式；不得保存 Codex 登录信息/API key。设置页按“AI 与执行、工程图谱、外观与组件”分区，但属于同一设置入口。AI 与执行区按讨论需求、制定计划、执行任务设置默认模型及其受支持挡位，并设置 0–3 次的 Agent 修复上限/验证指引。可用模型与挡位必须来自当前 Codex `model/list`，模型缺失或下线时回退到低挡可用选择并提示，不能送出不支持的值。对话中用户仍可手动修改选择；手动覆盖只对当前发送有效，不写回默认。

工程图谱区显示当前工程路径、最后成功索引时间、索引统计/状态，并提供重建操作；外观与组件区复用现有主题、色彩、动效和主题包编辑能力。页面导航来自同一 rail 入口，外观速切换按钮可继续保留为主题切换，不再保留独立的“外观与组件”孤立页面/抽屉入口。

## 边界情况

无模型、尚未连接 Codex、设置 JSON 损坏或 schema 更新时显示可恢复错误并保留可读的旧文件，不覆盖秘密或未知字段。模型默认项不支持某挡位时保存拒绝或明确回退。默认模型设置不能提升访问权限、跳过 Codex 权限审批或自动发送指令。工程图谱区的索引结果标记根路径和时间；重建期间可离开页面，状态不丢失。

## 验收条件

- 设置页从统一导航入口可达，至少显示 AI 与执行、工程图谱、外观与组件三个区域。
- 每种对话模式可配置 Codex 返回的模型及受支持挡位；重启后保留，失效默认值清楚提示。
- 对话页加载默认值，但人工临时选择不会改变保存预设；默认低挡策略不自动提升模型等级。
- 修复轮数校验在 0–3 范围，并随任务上下文传给 Agent。
- 工程图谱状态/重建按钮可用；主题设置和主题包既有功能可从统一页面访问。
- 无 Codex 连接、损坏设置、旧设置迁移和保存失败均有清晰反馈；设置中没有凭据字段。

## 附录

首版数据结构：`schemaVersion`、按工作模式映射的 `model` / `effort`、`maxVerificationRepairRounds`、`autoVerification`。缺失时以默认值填充；非法或不再支持的模型配置保留记录但不应用，并显示修复提示。主题视觉数据仍由既有外观服务持有；设置页统一入口不复制主题持久化合同。

## 实施细节

TaskReviews.cs：TaskReview 绑定 PlanId、Revision、Round、RunId/ThreadId/RunState，Baseline 用精确路径字典保存真实工作内容；ReviewFile 保存 Before/After、Fingerprint、Decision、Notes。变更集为开始基线与当前清单的路径并集，对比内容 SHA-256；仅大小写移动合并为带 OriginalPath 的审批文件。前后 UTF-8 小文本存独立 content-addressed blobs；二进制/超限仅保留内容指纹和大小，不提供回滚承诺。

文本行差异采用有界 LCS：共同前缀/后缀先剥离，中间区域 m*n≤1,000,000 时按最长共同子序列对齐，否则完整显示中间删除和增加；整体前后6000行容量限制独立于计算量。路径遍历拒绝越界和 reparse 链接。审批必须匹配修订/文件指纹，重新清点真实路径和内容；整体批准核对完整变更集，禁止尚有不通过文件。

Workbench：移除全部 Git API/产品 GitService，保留 HTTP 会话令牌和工程写锁。任务开始快照在 turn/start 前，completed 后异步生成审批差异，保存真实终态；初始化、停止、断连和退出记录不得污染上一轮。TaskId 承接退回任务，成功建立会话后 Resume，原基线不重建。任务审批与计划六阶段独立维护，避免跨两个存储的半成功状态变更，不伪造机器验收或计划关闭。

Web/review.js 与 index.html：左侧任务目录，右侧计划标题/摘要、文件列表/行差异/意见、整体审批和返回再执行。资料仍空选/多选，执行计划另选一份。保存时锁定本页编辑/切换，保留其它草稿；初始化待全部 defer 脚本加载完成后进行。退出脏状态含审批草稿。旧 Git 测试的历史夹具只留在测试工程，不进入产品程序集，不据其既有通过数字验收本次实现。

## 机器与 Agent 测试设计（按切片记录）

1. 开始前修改/未跟踪资源成为真实基线；之后代码、Prefab/.meta、配置的增删改及大小写移动只列本次变化，Docs/Tools/Library 不混入 Unity 审批。
2. 文本行意见绑定原/新行号；驳回无解释失败，逐文件通过后再变须重新审批，旧Revision/Fingerprint拒绝；未改变文件保留结论。
3. 二进制、空文件、非UTF-8、大文本和高换行密度明确说明且不冻结；快照含链接/外部写冲突失败，不静默漏项。
4. 整体批准只允许没有不通过文件且当前完整变更集一致；整体退回保存所有意见，已通过不变文件保持，反馈重跑仍使用最初基线。
5. Codex completed 与失败/停止/未知/退出分别记录事实；加载原会话失败不把任务发往其它聊天，外部任务新建会话；写任务不选计划拒绝，只读空选正常。
6. 保存期间不能覆盖新输入；刷新/切页保留草稿，重载失败可见，defer网络延迟不阻断页面初始化；所有用户字符串转义。

## 人工验收重点

选择计划并记录任务开始，修改少量 Unity 代码/配置/资源，查看整体摘要及真实差异；通过一个文件、驳回另一个文件并指定行意见，再整体退回。返回 AI 对话确认原会话、计划和所有意见正确，再发送执行；内容变化重新审批，不变结论保持。最后整体批准，本地文件和 Git 索引不被审批动作改写，计划不会自动关闭。

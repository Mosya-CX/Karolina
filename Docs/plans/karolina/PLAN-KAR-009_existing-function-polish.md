## 实施细节

沿用用户已完成的视觉主题、组件、外观与模块注册。Core负责文档资源合同、审批来源/说明与工具声明；Desktop负责只读说明生成、协议终态和调用适配；前端负责可见入口、筛选、选择与说明阅读。

### 文档与参考资料

需求与计划按编号自然倒序混排，每项明确类型，可按需求/计划筛选。默认隐藏废弃/关闭，重新隐藏时取消结束项的勾选。浏览标签或按标题/标签部分文字、顺序字符与多词筛选，#词限定标签。

计划保持事前plannedChanges与事后resourceRefs分离，真实关联必须有规范路径与依据；参考计划默认展开全选关联文件，支持单选和全部不选，发送时服务端校验归属。阅读计划有“关联代码与资源”入口，列存在情况并可文件管理器定位，不宣称内置Unity资源预览。旧关闭计划可以补现存职责对应源码，但明确它不证明历史原始改动或当期验收。

需求演进仍存正文，从章节生成完整时间线。标题目录支持h1–h6嵌套、最浅级默认展开、展开全部/折叠子级与窄窗入口。Ctrl+滚轮只缩放Markdown；导航、目录、输入与Windows窗口固定，WebView2原生缩放关闭。

### 任务审批

文件有agent/human/unknown来源，来源依据和说明均绑定冻结指纹。.meta永久排除显示/审批；用户确认由本人导入的资源按精确路径及冻结哈希标为人工来源，不进入审批文件列表，不按扩展名猜其它文件作者。

每文件先看Summary/WhatChanged/Why/Verification/Source，代码继续显示diff与行意见，资源不提供YAML、二进制或原始序列化差异入口。缺少当前版本说明不能批准Agent文件；仍可保存意见或退回。后台约3秒同步文件，按钮只保存人工任务摘要，不提交差异。

执行完成的结构化说明仅绑定有成功写入证明且写后哈希匹配的Agent版本。整体摘要剥离结构化JSON；只有说明代码块时仍以明确缺摘要提示进入待审批。旧任务可由只读Agent分析冻结差异补充说明，这不证明原作者、不修改Origin/Decision/Notes。内容容量在差异计算前受限；过大内容明确未完整分析。后台保留摘要、来源和意见草稿，同指纹新说明可更新而不覆盖Notes。

### 拓展工具

目录按语义组织，“项目构建”同页提供七个函数，游戏/UOS启动器各有自己的语义页面。注册支持group+operations，共用说明，每函数独立参数；父声明哈希保护子函数，拒绝嵌套/未知函数。人工调用不选择计划/继续任务，不创建Agent审批；保留工程锁、运行回执、Unity身份校验、菜单白名单及构建pending暂停。

说明生成增加独立模型与档位、低档模型默认政策、任务/运行绑定的可见真实进度及停止入口。开始/终态保存至工程本地状态；流式消息只更新内存，重启无终态明确显示中断。说明生成仍分析冻结材料，不能认领作者。连接/模型刷新改用独立codexConnectionGate，工具执行锁使用即时获取，避免连接慢时工具排队；真实任务/工具的工程锁不变。调用函数使用整组details及各项details折叠，按钮在使用说明/历史返回前即可操作。

## 事前文件预估与偏差

独立元数据保留起草时plannedChanges，并明确校正过程中新增模块/检查是估算补充。只修改Karolina工具源码、Docs及本地审批说明状态，不修改Unity Gameplay源码或资源。

原独立构建/启动函数声明已归入三组，九个重复声明移除，其函数定义保留在operations；资源索引、严格补丁、逐文件说明、混合资料检索、阅读缩放及原生检查拆为独立小模块。已有历史资源快照保留，删除的历史关联不伪造当前存在。

## 校正原因与交付

上一轮用户看到的是bin/Release旧页面，代理仅构建了隔离输出；同时旧实现的资源字段投影、全局缩放和工具任务选择不符合最终要求。上一轮23项DOM检查覆盖旧设计，不能当成本轮可用性的证明。此次明确修正源码、实际bin/Release与正式artifacts/current交付内容，并核对实际服务版本与文件哈希。

既有审批条目保留编号、基线、待审批状态、意见及中断事实。用户确认的人工导入资源按精确路径和冻结哈希排除；对可核对的资源配置补充逐文件冻结差异说明，不认领原作者、不宣称任务完成、不替用户批准。其它文件缺少来源或说明仍如实待确认，不能自动猜测。

## 人工验收重点

1. 参考资料应看到“需求/计划”标记、默认隐藏结束项、可浏览标签；选计划直接看到关联代码/资源，默认全选，可取消。
2. 计划阅读点“关联代码与资源”；需求点“演进”；标题目录可展开全部。鼠标在Markdown上Ctrl滚轮只改变正文。
3. 用户确认的人工导入资源不在文件列表；其它资源显示具体操作说明与限制。来源待确认时不冒充Agent，来源确认后才可批准。
4. 代码先说明再diff；保存任务摘要无需更新差异。驳回/整体退回保留解释，之后返回执行。
5. 构建工具一个页面七函数，无计划/继续任务选择。真实Unity构建只发一次，用户报告结束后恢复Unity操作。

新增反馈已完成校正并进入人工验收；本轮没有操作生产Git或改写Unity Gameplay/资源。r2机器测试与独立审查记录仅证明之前所审版本；r3增量只执行两个启动目录Release编译（0警告0错误）与独立只读源码审查（两项P2已修正，复核无剩余P1/P2），不继承38/38作为新增行为验证结果。人工验收还需确认审批页模型/档位及生成/停止进度、重启终态、工具折叠与即时调用。

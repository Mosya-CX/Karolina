# Karolina 独立工程规则

## 目标

代码遵守高内聚低耦合、关注点分离、依赖倒置、清晰边界、可测试可观测、简单实用和演进式设计。按实际需要建立边界，不为抽象而抽象。

## 程序边界

- Core 保存可独立验证的工程逻辑、文件索引、模型设置与协议无关的业务类型。
- Desktop 负责 WinForms 生命周期、本机 HTTP 服务、Codex/Unity 连接编排和 API 组合。
- Web 页面通过显式控制器依赖访问 API；前端模型政策保持可独立验证。
- 用户指定的 Unity 工程是外部数据源。图谱默认只读，Unity 写操作须由用户明确任务触发并保留真实回执。
- 每项外部工具声明实际参数、权限、输入约束和错误结果；不虚构 Harness 的能力。

## 质量与安全

- 新增第三方包、改变公开协议或移除必需层前先取得用户确认。
- 失败要可见并保留上次有效数据；不要用默认值覆盖无法读取的用户文件。
- 密钥由 Codex 或用户的外部凭据管理；Karolina 的设置文件不得包含凭据。
- 自动进度与验证结果只能来自真实事件/回执。工具调用完成不等于测试通过；缺少结构化终态须显示未确认。
- 测试必须验证实际行为，不得留空实现、吞异常、禁用测试或以截图代替验收。
